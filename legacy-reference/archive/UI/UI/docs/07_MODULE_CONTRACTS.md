# DOM-01 — Five Operational Environments

**Version:** 1.0.0-draft  
**Status:** CANONICAL known compositions; unknown cover/menu specifics require approval

## Global
Every module uses the same shell, cover, contextual menu, footer, tokens, fields, cards and Lightbox. No large generic title header. All preview data is synthetic and labeled as fixture data.

## LISTING
- Compact **two-column** grid of the ten canonical units: BR·02/U-1002, BR·03/U-1003, BR·04/U-1004, BR·05/U-1005, BR·07/U-1007, BR·08/U-1008, BR·09/U-1009, BR·10/U-1010, BR·27/U-2704B, BR·32/U-3208.
- Four aligned rows per room card: room/occupancy, maintenance, housekeeping, next date.
- Room Lightbox tabs: **ROOM · TENANT · UTILITIES · OPERATIONS · TERMS**.
- BR·07 balcony **NO VIEW**; do not invent a view.

## PEOPLE
- Shared SearchField, compact person rows and person dossier via Universal Lightbox.
- Person is canonical identity, not a duplicate tenancy/contact record.
- Person-to-tenancy relationship shown with synthetic fixtures only at this stage.

## DASHBOARD
- Three operational tiles: **MESSAGES · MAINTENANCE · HOUSEKEEPING**.
- Compact task/event cards; no legacy attention center, notification setup hero, or generic descriptive banner.

## CALENDAR
- Five rows of consecutive dates; infinite horizontal navigation where technically practical.
- TODAY Mustard; workload Amaranto; weekend inner squares ~20% smaller.
- Day Lightbox; event inline editing and swipe-delete interaction in fixture mode.
- Date/time picker follows shared touch-wheel contract.
- No duplicated page title or generic filter wall.

## SERVICES
- Shared canonical task shape across Services, Listing, Dashboard and Calendar: room + object + action; status PENDING / IN PROGRESS / DONE; priority NORMAL / URGENT.
- Hierarchical service → macro → category → object → action selection. Existing catalog reportedly contains 392 seeded nodes; do **not** copy data from legacy without verifying schema/source and explicit authorization.
- Demonstrate shared fixture projection across modules, not independent disconnected mock data.

## Covers & menus
A distinct cover and contextual menu are mandatory for each of the five environments. Their precise visual composition, artwork and action hierarchy are **UNKNOWN** until the owner supplies approved mockups/contract. This is a blocking design decision, not a license for agent invention.

## Acceptance
Switch all five environments, open contextual menus, use shared fields/Lightbox, see responsive grids, and observe one synthetic task reflected consistently in Services/Listing/Dashboard/Calendar. Clearly label all fixture operations.
